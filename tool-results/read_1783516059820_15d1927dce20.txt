    20→    20→**Audit findings (filed under "Known Issues" below):**
    21→    21→- ✅ Chrome ↔ `/api/github/scan-real` and `/api/vault` — shape match, no fix needed.
    22→    22→- ❌ VS Code `scanWorkspace` previously POSTed `{ repoUrl: "vscode-workspace" }` to `/api/scan`.     71→    71→### 1.3 Known limitations
    72→    72→
    73→    73→- **No MCP connect command.** The Chrome extension does not surface MCP config;
    74→    74→  use the dashboard (`/api/mcp-config`) or the VS Code / Cursor extension instead.
    75→    75→- **No restore flow in the popup.** Vault entries are listed as a count only;
    76→    76→  there is no UI to retrieve/restore a masked secret. Use the web dashboard.
    77→    77→- **API key is stored in `chrome.storage.local`** (unencrypted). Sufficient for
    78→    78→  a developer tool, but not for shared machines. **UNVERIFIED** whether Chrome's
    79→    79→  storage is encrypted at rest on every platform.
    80→    80→- **Scan results are limited to 30 files** by the backend
    81→    81→  (`src/lib/github-scanner.ts:94` slices `files.slice(0, 30)`). Large repos are
    82→    82→  under-scanned.
    83→    83→- **Rate limits.** GitHub's unauthenticated REST limit (60 req/h per IP) will
    84→    84→  throttle rapid scans. The extension does not pass a GitHub token today — only
    85→    85→  the ShadowPaste API key is sent. To scan private repos or lift the rate limit,
    86→    86→  the user must wait for a future extension update that adds a `token` field
    87→    87→  (the route already accepts `token` in the body, per `/api/github/scan-real`).
    88→    88→- **`host_permissions` includes `localhost:3000` only** by default. Production
    89→    89→  deployments on HTTPS hosts require editing `manifest.json` `host_permissions`
    90→    90→  before publishing to the Chrome Web Store.

   138→   138→### 2.3 Known limitations
   139→   139→
   140→   140→- **`scanWorkspace` runs locally; it does NOT persist a project/scan row in the
   141→   141→  backend.** The backend's `/api/scan` route persists a `Project` + `Scan` row
   142→   142→  in Prisma and writes an `auditLog` entry. The local scan in the extension
   143→   143→  does not — the findings are shown in the Webview only. If persistence is
   144→   144→  required, run the scan from the web dashboard instead.
   145→   145→- **`scanWorkspace` scans only currently-open text documents**, not the entire
   146→   146→  workspace folder. Files not opened in an editor are skipped. (Mitigation: open
   147→   147→  all files first, or use the dashboard's GitHub scan for full-repo coverage.)
   148→   148→- **Local detector is a byte-identical port.** `src/detector.ts` must be kept
   149→   149→  in sync with `src/lib/security/detector.ts` manually — there is no build-time
   150→   150→  guard. If the backend patterns change, update both files together.
   151→   151→- **Local score formula mirrors `src/lib/scanner.ts`.** Same manual-sync risk
   152→   152→  applies to `computeTrustScore` (deductions `{critical:25, high:12, medium:5, low:2}`)
   153→   153→  and `scoreToGrade` thresholds.
   154→   154→- **No restore command.** Once a secret is virtualized in the document and
   155→   155→  stored in the vault, the extension does not provide a "de-virtualize" command
   156→   156→  to swap the reference back for the raw secret. Use the web dashboard.
   157→   157→- **No config scan.** The backend's `scanGitHubRepo` also scans for risky
   158→   158→  configs (`*:*` IAM, `privileged: true`, TLS-disabled, etc.) via
   159→   159→  `CONFIG_PATTERNS`. The extension's local scan does NOT — it only finds
   160→   160→  secrets. (The `detector.ts` port has no `CONFIG_PATTERNS` block.)
   161→   161→- **Workspace scan score is informational.** Because the extension does not
   162→   162→  persist a scan, the score shown in the Webview is the only place it lives —
   163→   163→  it will not appear in the dashboard's project list or the trust leaderboard.
   164→   164→- **`engine.vscode: ^1.80.0`** — older VS Code versions are not supported.

   201→   201→### 3.3 Known limitations
   202→   202→
   203→   203→- **Inherits all VS Code extension limitations** (§2.3) because it re-exports
   204→   204→  `activate` / `deactivate` from `../../vscode/src/extension`.
   205→   205→- **The `cursorMcp` command writes a file the user must manually save** to
   206→   206→  `~/.cursor/mcp.json`. There is no auto-write — by design, to avoid touching
   207→   207→  the user's home directory without consent.
   208→   208→- **`<your-agent-api-key>` placeholder in the config** must be manually replaced
   209→   209→  with a real ShadowPaste agent API key. The extension does not have access to
   210→   210→  the user's agent keys (they live in the backend's `Agent` table).
   211→   211→- **Cross-extension import.** `src/extension.ts` imports from
   212→   212→  `../../vscode/src/extension`. This means the VS Code extension's source must
   213→   213→  be present at build time. If `extensions/vscode/src/extension.ts` is moved or
   214→   214→  renamed, the Cursor extension breaks.
   215→   215→- **Build output layout.** Because `tsconfig.json` uses `rootDir: ".."`, the
   216→   216→  compiled JS is emitted at `out/cursor/src/extension.js` and
   217→   217→  `out/vscode/src/extension.js` (not `out/extension.js`). The `package.json`
   218→   218→  `main` field has been updated to match — do not revert it.
   219→   219→- **No separate Cursor permission UI.** The zero-trust permission prompt is
   220→   220→  served by the backend's web dashboard, not by the editor. Cursor's agent
   221→   221→  will be blocked silently until the user approves in the dashboard.

   249→   249→### 4.3 Auth flow
   250→   250→
   251→   251→1. User obtains a ShadowPaste API key from the web dashboard (TBD — there is
   252→   252→   no `/api/agents/api-key` route today; keys are seeded via `/api/seed` for
   253→   253→   dev). **UNVERIFIED** that a user-facing key-issuing flow exists.
   254→   254→2. User pastes the key into the extension's settings (Chrome popup / VS Code
   255→   255→   settings / Cursor settings).
   256→   256→3. Every extension `fetch` attaches `Authorization: Bearer <apiKey>` IF a key
   257→   257→   is set; otherwise the request goes anonymous.
   258→   258→4. Backend `getContext(req)` resolves the key to a `User` + `Org`; if missing,
   259→   259→   `anonymousContext()` is used (orgId: `"default"`). **UNVERIFIED** that the
   260→   260→   backend actually enforces auth on these routes in production — the V20
   261→   261→   reality report flags 23/31 routes with no auth check (item #10).
   262→   262→5. The Cursor MCP config returned by `/api/mcp-config` embeds a
   263→   263→   `<your-agent-api-key>` placeholder in `headers.Authorization` — the user
   264→   264→   must replace it manually before saving `~/.cursor/mcp.json`.
   265→   265→
   266→   266→### 4.4 Phase-1 invariant ("the same secret behaves the same everywhere")
